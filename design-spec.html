Open items & differences between iOS / Android

The screens render identically on both platforms. React Native uses the same component tree on iOS and Android; the differences you'll see on a real device:

  • iOS: rounded notch / Dynamic Island handled by SafeAreaView; status bar light text on the dark background.
  • Android: bottom system gesture bar adds ~16pt — already accounted for via SafeAreaView. Status bar follows the app's dark theme.
  • Adaptive icon (Android): uses assets/adaptive-icon.png on the dark navy background defined in app.json. Now drawn — was a 1×1 placeholder before this build.
  • App icon (iOS): uses assets/icon.png. Now drawn from a recreation of the coral DNA mark you sent — pixel-perfect requires uploading the source file as an attachment, not pasted inline.

What's left to make this functional

  • Real authentication. The Welcome form just flips an in-memory flag. No token storage, no API call. Needs Apple Sign-In, email/password, or the existing dna_ API key flow against a real backend.
  • Real data. Every number, name, and credential on every screen is hardcoded. Needs API calls (provider.getDashboard, credentials.list, signals.get, etc.).
  • Action wiring. Approve, Verify, Renew, Add, Resolve credential — all currently no-ops. Each needs a backend endpoint and an onPress handler.
  • Persistence. No expo-secure-store wiring yet — relaunching the app forgets the session.
  • Push notifications. Urgent-signal alerts won't actually arrive. Requires Expo push tokens and a backend trigger.
